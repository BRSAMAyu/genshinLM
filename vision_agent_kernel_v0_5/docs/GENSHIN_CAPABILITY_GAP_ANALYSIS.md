# 原神场景能力缺口分析

> **分析日期**：2026-05-30
> **分析范围**：6 份场景/能力文档的交叉对比
> **分析结论**：场景引用 306 个唯一能力ID，全部在 checklist 中有定义；checklist 中有 147 个能力ID未在任何场景文档中被引用

---

## 一、场景引用但 checklist 缺失/不足的能力

**结论：场景文档中引用的全部 306 个能力ID均已在 checklist 中定义，无缺失。**

这表明场景文档的编写者严格遵循了 checklist 的能力编号体系，所有引用均可追溯到 checklist 中的具体条目。场景覆盖最密集的能力集中在感知层（P-01/P-06/P-22）、对话（D-01/D-02）、战斗（C-01/C-03）和导航（N-01/N-03）等基础能力上。

### 关键结论

1. **场景与 Checklist 的编号体系完全一致**：所有 306 个场景引用的能力ID均可在 Checklist 中找到对应条目，无"幽灵引用"。

2. **未覆盖的 147 个能力全部来自 Appendix D (Corner Cases)**：这些是深度研究的补充条目，原 274 条主清单中的能力全部被场景覆盖。

3. **感知层 (P) 的未覆盖率最高** (28/57 = 49.1%)：大量 OCR/VLM/检测类的精细化能力未被场景文档引用。这是因为场景文档倾向于引用高阶能力（如"菜单文字 OCR"），而 Corner Cases 拆分了更细的子能力。

4. **对话 (D)、抽卡 (W)、日常 (DL)、元学习 (L) 达到 100% 覆盖**：这些类别的能力数量较少，且全部被日常循环场景覆盖。

5. **导航 (N) 的覆盖率最高达 94.4%**：仅 N-18 (三维空间导航) 未被场景引用，但几乎所有场景都依赖导航能力。

6. **最需优先补充的场景方向**：
   - Boss 战前准备与检查流程（P0: R-33, R-32）
   - 异常中断与安全恢复流程（P0: I-06, I-07, P-32）
   - 稻妻/枫丹/纳塔区域特有机制（P1: Q-35, E-42, E-43）
   - UI 弹窗异常处理（P1: U-45, U-47, U-50, U-52）
