# Genshin Impact 感知与输入精度需求矩阵

> Sparkle Project — Vision Agent Kernel v0.5 端侧视觉交互 Agent 精度量化基准
>
> 本文档为感知平面 (Perception)、控制平面 (Control)、执行平面 (Execution) 提供可量化的精度目标，
> 作为 YOLO 检测器、BoT-SORT 跟踪器、CameraServo、InputWorker 等组件的验收标准。

## 一、视觉感知需求矩阵

视觉感知需求按场景类型分解，每类场景对应不同的检测目标集合、精度容忍度和实时性约束。
所有检测目标最终通过 `Observation` 结构体发布到 StateBus 的 `latest_observation` 槽位，
高频帧写入 `observation_ring` (300 帧环形缓冲区)。

### 1.1 检测置信度阈值分层说明

置信度阈值按代价敏感度分四档：

| 档位 | 阈值范围 | 适用场景 | 误检/漏检权衡 |
|---|---|---|---|
| **A 级 (安全关键)** | ≥0.95 | Boss 技能预警、氧气条、阶段指示器、弹窗检测 | 宁可漏检也不误检；漏检触发保守回退策略 |
| **B 级 (功能关键)** | ≥0.85-0.95 | 敌人检测、机关状态、UI 按钮、对话选项 | 平衡型；漏检触发重试，误检触发容错 |
| **C 级 (效率敏感)** | ≥0.75-0.85 | 宝箱、采集物、地标、图标匹配 | 宁可误检也不漏检；误检代价小 (多走一步) |
| **D 级 (增强型)** | ≥0.60-0.75 | 掉落物、海底采集物、远距离预警 | 低优先级，不影响核心流程 |

### 1.2 检测频率与输入频率的协调

Perception 平面以 20 Hz 上限运行（受限于 DXcam 捕获 + YOLO 推理延迟），
Control 平面以 10 Hz 决策，Execution 平面以 30 Hz 执行输入。
三者异步解耦，高频检测结果通过 RingBuffer 下采样给低频消费者。

```
Perception (20Hz) ──Observation──→ StateBus.observation_ring (300 frames)
                                      │
Control (10Hz)    ←──latest_observation──┘
                                      │
Execution (30Hz)  ←──MovementIntent/CameraIntent──┘
```

## 二、输入操作精度需求矩阵

输入操作由 Control 平面生成 Intent（`MovementIntent` / `CameraIntent`），
经 InputLease 授权后由 Execution 平面的 InputWorker 执行。
所有物理输入调用均通过 `SafeWindowInputBackend` 或 `ConsoleInputBackend` (dry-run)。

| 操作类型 | 精度要求 (px) | 操作频率上限 | 容错范围 | 失败后果 | 原神典型示例 | 实现约束 |
|---|---|---|---|---|---|---|
| **点击 (精确)** | 目标中心 ±4px | 5 Hz | ±8px (2x 容错) | 高 — 点错按钮触发错误页面或取消关键操作 | UI 按钮 "确认" / "合成" / "开始挑战" | 点击前截图校验指针位置 |
| **点击 (区域)** | 目标区域 ±20px | 2 Hz | ±40px | 低 — 区域内点击无严格位置约束 | 大地图传送、调查点交互、NPC 对话触发 | 区域中心 ± 半径内随机偏移防检测 |
| **长按** | 目标中心 ±8px (起始) | 0.5 Hz (单次持续 1-3s) | ±16px 漂移容忍 | 中 — 提前释放导致蓄力不足或采集失败 | 弓箭蓄力、采集 (F 键长按)、重击 | 需要按压时长监控 + 视觉反馈校验 |
| **拖拽** | 路径精度 ±10px | 1 Hz (单次拖拽) | ±20px | 中 — 拖拽不到位需重新操作 | 圣遗物锁排序、背包物品拖拽、地图平移 | 起始/结束点视觉确认 |
| **快速连点** | 无需空间精度 | 8-12 Hz (100-125ms 间隔) | ±20ms 时序抖动 | 中 — 连点频率不够导致挑战失败 | 烹饪完美区、部分限时挑战 | 需测量实际点击间隔并自适应调整 |
| **方向键移动** | — (键盘输入) | 持续 (每 50ms 更新方向) | ±100ms 延迟容忍 | 高 — 错误方向导致坠崖/进毒区 | WASD 移动、水中游泳 (含垂直维度)、滑翔 | 需与 ObstacleField 实时联动；断触后 200ms 内释放所有方向键 |
| **视角控制** | 鼠标位移 ±50px (最终落点) | 15 Hz (鼠标事件) | ±100px | 高 — 视角偏移导致目标丢失或误判环境 | 右键拖拽旋转视角、弓箭瞄准 | CameraServo 将像素误差转为 yaw/pitch 增量；需惯性阻尼防过冲 |
| **元素战技/爆发** | — (键盘 E/Q) | 按需 (受 CD 限制) | 无容错 (按键即触发) | 高 — 误放技能浪费 CD 和能量 | E 战技 / Q 爆发 | 需校验当前角色 CD 状态和元素能量是否足够 |
| **跳跃 + 冲刺** | 时序精度 ±50ms | 按需 | ±100ms | 高 — 时机错误导致无法到达目标平台 | 冲刺跳、二段跳区域、风之翼展开时机 | 建议基于角色动作状态 (地面/空中) 判断时机而非纯计时 |
| **瞄准射击** | 目标中心 ±10px (屏幕空间) | 1 Hz (瞄准 + 射击循环) | ±30px (命中判定宽松) | 中 — 未命中浪费蓄力时间 | 弓箭角色蓄力瞄准弱点、部分解谜射击目标 | 多步流程：进入瞄准模式 → 微调视角 → 蓄力 → 释放；每一步需视觉确认 |
| **切换角色** | — (键盘 1-4) | 按需 (受切换 CD ~1s 限制) | 无容错 | 中 — 切错角色打乱元素反应节奏 | 数字键 1-4 切换角色 | 需读取当前队伍排列确保切换目标正确 |
| **交互键** | — (键盘 F) | 按需 | 无容错 | 低 — 误触仅产生无效交互提示 | F 键捡取/对话/开宝箱/操作机关 | 需确认交互提示可见时才触发 |

### 2.1 Deadman Switch 触发条件

所有输入操作受 Deadman Switch 保护，以下任一条件触发立即 `release_all()`：

| 条件 | 检测方式 | 响应延迟上限 |
|---|---|---|
| InputLease 过期 | 租约超时 (默认 5s，可续约) | 50ms (chunked-wait 轮询) |
| InputWorker 线程异常退出 | 线程心跳检测 | 100ms |
| 目标窗口失去焦点 | Win32 `GetForegroundWindow` 轮询 | 200ms |
| F9 紧急停止键 | 全局热键钩子 | 50ms |
| Ctrl+C / SIGTERM | 信号处理器 | 即时 |
| Watchdog 超时 | 心跳表超时 (默认 3s 无心跳) | 50ms |

### 2.2 输入操作的视觉校验闭环

每次有精度要求的操作执行后，必须在下一个 Observation 帧中校验操作效果：

```
InputWorker 执行点击 → 等待 2 帧 (~100ms) → Perception 捕获新帧 → 
VisualCheckpoint 校验：目标区域是否发生变化 (按钮消失/页面跳转/特效出现) →
  ├─ 校验通过 → 继续下一步
  └─ 校验失败 → 重试 (最多 3 次) → 仍失败 → 触发 RecoveryPolicy
```

## 三、状态管理需求矩阵

状态是 Sparkle Agent 的"记忆"——跨 Perception 帧持久化的世界理解。
状态存储分层：热状态 (StateBus 的 `LatestSlot`)、温状态 (本地 SQLite/JSON)、冷状态 (会话日志 JSONL)。

| 状态类型 | 更新频率 | 存储方式 | 跨场景持久性 | 丢失后果 | 数据来源 | 精度/粒度 |
|---|---|---|---|---|---|---|
| **角色位置** | 每帧 (20 Hz 原始) → 下采样 2 Hz 持久化 | 热：StateBus.latest_observation 冷：JSONL 时间序列 | 跨场景持久 (用于断点续跑) | 高 — 角色定位丢失导致路径重规划从锚点开始，最坏回退到最近传送点 | 小地图图标 + 地标三角定位 + 任务导航距离读数 | 大世界 XYZ (相对坐标系)，精度 ±5m |
| **任务进度** | 事件驱动 (任务步骤变化时) | 温：内存 dict + JSON 快照 | 跨场景、跨会话持久 (关键) | 极高 — 任务状态丢失等于整个会话白费 | OCR 任务面板文字 + 任务导航标记 | 任务 ID + 当前步骤序号 + 步骤描述文本 |
| **角色状态 (HP/体力/元素能量/附魔)** | HP/体力 5 Hz；能量/附魔 10 Hz | 热：StateBus.latest_slot | 不跨场景 (仅当前战斗/探索有效) | 高 (战斗中) / 低 (非战斗) — HP 误判导致未及时治疗角色阵亡 | UI HUD 固定位置像素采样 | HP 百分比 ±3%；体力百分比 ±5%；能量 (充能图标亮暗判定) |
| **队伍状态** | 1 Hz (或切换时立即更新) | 热：StateBus.latest_slot | 不跨场景 | 中 — 切错角色或对已阵亡角色下达指令 | 右侧队伍头像栏 OCR + 血条采样 | 4 角色排列 (1-4) + 各自存活/阵亡 + CD 状态 |
| **背包状态** | 事件驱动 (拾取/使用/丢弃后) | 温：JSON 缓存 + 增量更新 | 跨场景持久 | 低 — 仅影响物品数量判定和培养决策 | 背包界面 OCR + 图标匹配 (按需打开扫描) | 物品 ID + 数量 + 品质 |
| **UI 状态 (界面层级/弹窗/加载)** | 10 Hz (持续监控) | 热：StateBus.latest_slot | 不跨场景 | 高 — UI 层级误判导致操作发送到错误界面 | 屏幕边缘特征 + 弹窗模板匹配 + 加载图标检测 | 状态机：Overworld / Menu / Dialog / Loading / Cutscene / Combat |
| **战斗状态** | 15 Hz (战斗中) | 热：StateBus.latest_slot | 不跨场景 (战斗结束后清除) | 高 — 敌我状态丢失导致战术决策错误 | 敌人血条 + Boss UI + 元素附着图标 | 敌人列表 [{id, HP%, 元素附着, 距离}] + Boss 阶段 + 护盾类型 |
| **探索状态 (宝箱/神瞳/锚点)** | 事件驱动 (发现/解锁时) | 温：JSON 持久化 (按区域索引) | 跨场景、跨会话持久 | 中 — 丢失导致重复探索已清区域 | 地图标记变化 + 宝箱开启动画检测 + 传送锚点激活特效 | 区域 ID + 发现物类型 + 坐标 + 状态 (已开启/未开启) |
| **好感度/素材积累 (可选)** | 事件驱动 | 冷：会话日志 | 跨会话 | 极低 — 非功能需求 | 战斗结算画面 OCR + 获得物品弹窗 | 角色好感度经验 + 素材掉落统计 |

### 3.1 状态恢复优先级

当系统从断点恢复 (crash recovery) 或会话重新启动时，状态恢复按以下优先级加载：

1. **P0 (立即)** — 任务进度、角色位置 (大世界 XYZ)
2. **P1 (首次战斗前)** — 队伍状态、角色 HP/能量
3. **P2 (按需延迟)** — 背包状态、探索状态
4. **P3 (可选)** — 好感度/素材统计

### 3.2 状态冲突解决

当视觉检测到的状态与内存中的缓存状态不一致时：

```
冲突检测 → 置信度比较 →
  ├─ 视觉置信度 > 0.90 → 以视觉为准，覆盖缓存
  ├─ 视觉置信度 0.70-0.90 → 标记为 "tentative"，等待下一帧确认
  └─ 视觉置信度 < 0.70 → 维持缓存，记录偏差日志
```

## 四、场景复杂度评分

- **感知复杂度**：检测目标数量 × 多样性 × 遮挡/光照变化 × 实时性要求

- **状态复杂度**：需跟踪的状态变量数量 × 更新频率 × 状态间依赖关系

| 场景 | 感知复杂度 (1-10) | 操作复杂度 (1-10) | 状态复杂度 (1-10) | 总分 (/30) | 难度等级 | 说明 |
|---|---|---|---|---|---|---|
| **大世界导航** | 6 | 3 | 4 | 13 | ★★☆☆☆ 中等偏易 | 检测目标多但分散，操作简单 (WASD+视角)，状态主要是位置+任务导航。主要挑战在远距离小目标和地形障碍。 |
| **普通战斗** | 7 | 5 | 5 | 17 | ★★★☆☆ 中等 | 多敌人检测+血条监控+元素附着跟踪；操作涉及战技/爆发/冲刺/切换角色；状态包含敌我双方。 |

## 五、性能预算建议

基于场景复杂度评分的差异化性能预算分配。预算以端侧典型硬件 (RTX 3060 笔记本 GPU + 16GB RAM) 为基准，
CPU 推理回退方案见 5.2 节。

### 5.1 分场景性能预算

| 场景 | 目标 FPS (Perception) | 检测延迟上限 (ms) | 操作延迟上限 (ms) | 内存预算 (MB) | GPU 预算 (%) | 说明 |
|---|---|---|---|---|---|---|
| **大世界导航** | 10 | 100 | 100 | 800 | 40% | 低频率、低延迟要求。可降低 YOLO 输入分辨率 (416×416)。内存用于地形特征缓存。 |
| **普通战斗** | 15 | 66 | 50 | 600 | 55% | 中等频率。YOLO 输入 640×640。操作延迟要求更严格 (战斗响应)。内存用于多目标跟踪状态。 |
| **Boss 战** | 20 | 50 | 33 | 500 | 70% | 最高频率和最低延迟要求。YOLO 输入 640×640、NMS 阈值收紧。额外加载 Boss 专属检测头。操作必须亚 50ms 响应。 |
| **UI 操作** | 5 | 200 | 50 (点击) / 200 (拖拽) | 300 | 20% | UI 场景无需高频检测。OCR 和图标匹配可按需触发而非持续运行。操作精度高于检测频率。 |
| **对话** | 3 | 333 | 200 | 200 | 10% | 接近静态场景。仅需检测对话选项变化和结束条件。 |
| **解谜** | 10 | 100 | 100 | 400 | 40% | 中等检测频率。机关状态变化检测是主要算力消耗。 |
| **水下 (枫丹)** | 15 | 66 | 66 | 550 | 50% | 3D 移动对操作延迟敏感。水下光照条件需额外预处理 (对比度增强)。氧气条持续高频监测。 |
| **深境螺旋** | 20 | 50 | 33 | 600 | 75% | 与 Boss 战同级甚至更高要求。时间压力下无法容忍检测失败重试。双队状态需额外存储。 |
| **日常循环** | 5 | 200 | 100 | 350 | 25% | 可大量复用缓存模板。低频低算力。 |
| **过场动画** | 3 | 333 | — (不操作) | 150 | 5% | 仅需检测过场开始/结束。算力可完全释放给后台任务。 |

### 5.2 性能降级策略

当硬件资源不足或温度节流时，按以下优先级逐级降级：

| 降级等级 | 触发条件 | Perception 降级 | Control 降级 | 风险 |
|---|---|---|---|---|
| **L0 (正常)** | GPU < 80%, 温度 < 80°C | 全能力 | 全能力 | 无 |
| **L1 (轻度降级)** | GPU > 80% 或温度 > 80°C | 降低检测频率至 80%，降低输入分辨率至 512×512 | 正常 | 极低 — 大世界导航仍充分 |
| **L2 (中度降级)** | GPU > 90% 或温度 > 85°C | 降低至 50% 频率，关闭非战斗场景的装饰性检测 (宝箱/采集物) | Control 降频至 5Hz | 中 — Boss 战性能不足 |
| **L3 (重度降级)** | GPU > 95% 或温度 > 90°C | 仅保留安全关键检测 (氧气条/技能预警/Boss 阶段)，其余关闭 | 仅保留 Deadman Switch，停止主动操作 | 高 — 仅维持存活，放弃任务推进 |
| **L4 (紧急)** | 硬件节流触发 | 全部停止 | 全部停止 + release_all() | 极高 — 系统进入 EMERGENCY_STOPPED 模式 |

### 5.3 检测模型预算分配

基于场景自适应加载不同的检测模型组合，降低常驻 GPU 内存：

| 模型组件 | 常驻/按需 | 显存占用 (MB) | 适用场景 | 加载延迟 (ms) |
|---|---|---|---|---|
| YOLO 基础目标检测 (80 类 COCO + 原神扩展 20 类) | 常驻 | 350 | 全部 | 0 (预加载) |
| OCR 文字识别 (PaddleOCR / TrOCR) | 按需 | 200 | UI/对话/任务面板 | 500 |
| 图标模板匹配库 (物品/技能图标 200+ 模板) | 按需 | 80 (特征缓存) | UI/背包 | 200 |
| Boss 专属检测头 (弱点/技能预警/阶段指示) | 按需 (Boss 战加载) | 120 | Boss 战 | 300 |
| 元素附着分类器 (7 元素 + 无) | 常驻 (轻量) | 15 | 战斗 | 0 |
| 小地图定位模块 (三角定位 + 锚点匹配) | 按需 | 30 | 大世界导航 | 150 |
| 地形分割 (可通行区域 + 悬崖检测) | 按需 | 100 | 导航/探索 | 400 |

**总常驻显存预算**：~365 MB (YOLO + 元素分类器)
**峰值显存预算 (Boss 战全开)**：~750 MB (常驻 + OCR + Boss 专属 + 小地图)
**目标总 GPU 显存预算**：< 2 GB (为游戏本体留足余量)

### 5.4 延迟预算链分析

端到端延迟从光子到达屏幕到输入事件生效的完整链路：

```
屏幕渲染 (~8ms @120Hz / ~16ms @60Hz)
  → DXcam 捕获 + 传输 (~5ms)
  → YOLO 推理 (15-30ms，视场景和分辨率)
  → BoT-SORT 跟踪更新 (~3ms)
  → Observation 构建 + StateBus 发布 (~1ms)
  → Control 决策 (LLM/规则混合，5-50ms)
  → Intent 生成 (~1ms)
  → InputWorker 执行 (OS 输入注入 ~2ms)
  → 游戏处理 (~8ms @120Hz / ~16ms @60Hz)
────────────────────────────────────────
总延迟: 约 43-113ms (最优/典型) 至 150ms (含 LLM 决策)
```

**Boss 战延迟预算分配** (目标总延迟 < 100ms)：
- 捕获+推理+跟踪：≤ 50ms (严格上限)
- Control 决策：≤ 30ms (需规则优先，LLM 仅做战术建议)
- 执行：≤ 20ms

**大世界导航延迟预算分配** (目标总延迟 < 200ms)：
- 捕获+推理+跟踪：≤ 100ms
- Control 决策：≤ 80ms (可容纳 LLM 推理)
- 执行：≤ 20ms

### 5.5 感知失败模式与恢复策略矩阵

每种检测目标的典型失败模式及对应的恢复策略。感知失败不应导致系统卡死，
必须设计优雅降级路径。

| 检测目标 | 典型失败模式 | 根因分析 | 恢复策略 | 恢复时间上限 (ms) | 降级行为 |
|---|---|---|---|---|---|
| 敌人位置检测 | 遮挡 (特效/地形/其他敌人) | YOLO 特征被覆盖 | 启用 BoT-SORT 预测模式 (基于上一帧速度外推) | 500 (预测可维持 10 帧) | 预测位置置信度逐帧衰减至 0；3s 无检测则移除目标 |
| 敌人位置检测 | 光照突变 (昼夜切换/元素爆发) | 曝光变化改变特征分布 | 检测器输入归一化自适应 (直方图均衡) | 300 | 短暂回退到先验位置 + 增大搜索窗口 |
| Boss 阶段指示器 | UI 重叠 (伤害数字/特效遮挡) | 阶段指示器被战斗特效短期覆盖 | 时序平滑：连续 3 帧多数投票判定阶段 | 150 (3 帧 × 50ms) | 保持上一确认阶段，禁止阶段切换操作 |
| 技能范围预警 | 地面贴花与地形纹理混淆 | 地面颜色/图案相近 | 运动特征辅助：预警贴花通常有膨胀动画 | 100 | 保守策略：所有红色地面区域视为危险 |
| OCR 文字识别 | 多语言混合 (中/日/英同屏) | 字符集模糊导致误识别 | 语言检测预分类 + 多模型加权投票 | 500 | 回退到图标特征匹配 (任务标记颜色/位置) |
| OCR 文字识别 | 艺术字体/特效文字 | 超出训练分布 | 模板匹配回退 (常见关键词词组库) | 800 | 标记为不可识别，跳过该文字区域 |
| 小地图定位 | 锚点被任务标记覆盖 | 图标重叠 | 基于距离读数的三角定位不依赖图标识别 | 200 | 使用上一已知位置 + 动作里程计推算 |
| 小地图定位 | 传送后地图完全变化 | 区域跳变 | 锚点数据库全局匹配 (不依赖上一位置先验) | 1000 | 等待玩家手动导航至已知区域后重新初始化 |
| 氧气条 (水下) | UI 闪烁/透明度变化 | HP 变动时氧气条短暂偏移 | 固定 ROI 均值滤波 (滑动窗口 5 帧) | 250 | 保守估计：按最快耗氧速率推算剩余时间 |
| 弹窗/模态框 | 半透明弹窗 / 渐入动画中 | 透明度变化期间边缘特征弱 | 弹窗生命周期状态机 (appearing → visible → disappearing) | 300 | appearing 阶段暂停操作等待完全可见 |

### 5.6 跨场景过渡的精度切换策略

场景切换时 (如大世界 → 战斗、战斗 → 对话、探索 → 水下)，
感知和操作的精度需求会发生突变。平滑切换策略如下：

| 场景过渡 | 切换检测延迟 (ms) | 检测依据 | 精度切换策略 | 风险与缓解 |
|---|---|---|---|---|
| 大世界 → 战斗 | 200 | HUD 变化 (技能栏出现) + 敌人血条出现 + 战斗音乐检测 (可选) | Perception 10→15Hz；加载元素附着分类器 | 敌人已生成的 200ms 窗口内 Agent 可能尚未就绪 → 初始姿态设为防御 (盾/闪避优先) |
| 战斗 → 大世界 | 500 | 所有敌人血条消失持续 1s + 技能栏恢复 | Perception 15→10Hz；卸载元素附着分类器 | 防止战斗结束误判 (敌人脱战但未消失) → 1s 滞后确认 |
| 大世界 → 水下 | 300 | 氧气条出现 + 角色动作切换为游泳 + 水面特效 | 加载水下敌人检测模型 + 共鸣球分类器；开启氧气条高频监控 (10Hz) | 入水瞬间视角变化剧烈 → 暂停操作 500ms 等待视角稳定 |
| 水下 → 大世界 | 300 | 氧气条消失 + 角色恢复站立 | 卸载水下专属模块 | 出水位置不确定 → 出水上岸后重新定位 |
| 任意 → 对话 | 200 | 对话 UI 出现 (选项/字幕/黑边) | 冻结所有战斗/移动操作；Perception 降至 3Hz (仅监控对话状态) | 对话中的战斗 (部分剧情触发) → 对话结束检测需加速 |
| 对话 → 任意 | 100 | 对话 UI 消失 | 恢复场景对应配置 | 对话后场景可能变化 (剧情传送) → 强制全状态重新校验 |
| 任意 → 过场动画 | 300 | 上下黑边 + 字幕出现 | 暂停所有操作；release_all()；Perception 降至 3Hz | 过场可能嵌入战斗 → 恢复后需检查战斗状态 |
| 过场动画 → 任意 | 200 | 黑边消失 + HUD 恢复 | 重新初始化场景检测；全状态刷新 | 剧情可能导致角色位置/队伍变化 → 放弃所有缓存状态 |
| 任意 → 加载画面 | 500 | 全屏白色/黑色 + 加载图标 (七元素符号) | release_all()；冻结全部模块；等待加载完成事件 | 加载时间不确定 (数秒至数十秒) → 心跳保持，禁止超时误报 |
| 加载画面 → 任意 | 500 | 加载图标消失 + 画面恢复 | 全状态重新初始化；场景分类器重新判定 | 加载后场景类型未知 → 通用感知模式启动，后续自适应切换 |

### 5.7 精度需求的测试验证方法

| 验证维度 | 测试方法 | 通过标准 | 测试数据集要求 |
|---|---|---|---|
| 检测精度 (mAP) | 标注数据集评估 (COCO 指标) | 通用目标 mAP@0.5 ≥ 0.75；安全关键目标 mAP@0.5 ≥ 0.90 | 每类目标 ≥ 200 标注样本，覆盖 3 种光照 + 3 种天气 + 5 个区域 |
| 检测延迟 | 端到端时间戳测量 (帧捕获到 Observation 发布) | P50 < 50ms, P99 < 100ms (Boss 战模式) | 连续运行 10 分钟真实场景，≥ 10000 帧 |
| 跟踪稳定性 (MOTA) | BoT-SORT 跟踪器评估 | MOTA ≥ 0.70；ID Switch < 5 次/分钟 | 多目标战斗场景 (≥4 敌人)，≥ 5 分钟 |
| 操作精度 | 点击坐标与实际按钮中心的像素偏差测量 | 精确点击 ±4px；区域点击 ±20px | UI 操作测试集 (50+ 不同按钮/控件) |
| 操作延迟 | Intent 生成到 OS 输入事件时间戳差值 | P50 < 20ms, P99 < 50ms | 连续 1000 次操作 |
| 状态一致性 | 视觉检测状态与游戏实际状态的人工对比 | 关键状态 (HP/任务/UI层级) 一致性 ≥ 98% | 10 个完整任务流程，每流程 ≥ 100 个状态检查点 |
| 场景切换可靠性 | 自动遍历所有场景过渡类型 | 切换检测准确率 ≥ 95%；误切换率 < 1% | 每类过渡 ≥ 50 次 |

## 附录 B：感知精度与输入精度的联动关系

```
感知精度 (检测框 IoU / 关键点误差)
        │
        ├──→ 影响 CameraServo 瞄准精度
        │       像素误差 → yaw/pitch 增量 → 视角调整
        │       检测框抖动 → 视角振荡 → 需 EWMA 平滑
        │
        ├──→ 影响 MovementIntent 路径精度
        │       目标位置误差 → 路径终点偏移 → 到达判定失败
        │
        ├──→ 影响 InteractionIntent 触发时机
        │       交互提示误检/漏检 → 过早/过晚触发 F 键
        │
        └──→ 影响 ProgressSupervisor 进度判断
                检测失败次数 → Frustration 上升 → RecoveryPolicy 介入
```

**核心原则**：感知精度决定操作精度的理论上限。当检测 IoU < 0.5 时，
不应生成任何需要像素级精度的操作 Intent，应降级为区域级操作或触发 RecoveryPolicy。

## 附录 C：元素反应检测的特殊精度要求

元素反应是原神战斗系统的核心机制。正确检测和利用元素反应直接影响输出效率。

| 反应类型 | 检测依据 | 视觉特征 | 检测精度要求 | 误判后果 | 操作窗口 |
|---|---|---|---|---|---|
| **蒸发** (水+火) | 伤害数字颜色 + 倍率文字 | 橙色大字 "蒸发" + 1.5x/2.0x 倍率标识 | ≥0.90 | 低 — 蒸发几乎总是正向收益 | 持续输出 |
| **融化** (火+冰) | 同上 | 橙色大字 "融化" + 1.5x/2.0x | ≥0.90 | 低 | 持续输出 |
| **感电** (水+雷) | 敌人身上紫色电弧特效 | 跳动的紫色闪电链 | ≥0.85 | 低 | 持续 DOT |
| **超导** (冰+雷) | 白色爆炸特效 + 敌人 debuff 图标 | 冰雾爆炸 + 物理抗性降低图标 | ≥0.85 | 中 — 物理队核心，错过影响输出 | 12s debuff 窗口 |
| **超载** (火+雷) | 红色爆炸特效 + 击飞 | 火焰爆炸 + 敌人位移 | ≥0.80 | 低 — 击飞效果明显 | 击飞期间敌人无敌 |
| **扩散** (风+任意) | 绿色旋风 + 附着元素色扩散 | 风漩涡 + 彩色扩散波 | ≥0.85 | 中 — 翠绿套减抗核心 | 10s 减抗窗口 |
| **结晶** (岩+任意) | 地面彩色晶片掉落 | 对应元素颜色的六角晶体 | ≥0.70 | 低 — 仅产生护盾 | 晶片存在 15s |
| **燃烧** (草+火) | 持续火焰 DOT 视觉效果 | 敌人身上持续火焰 | ≥0.80 | 低 | 持续 DOT |
| **绽放/超绽放/烈绽放** (草+水+雷/火) | 草原核生成 + 后续反应 | 绿色种子 → 追踪弹/范围爆炸 | ≥0.85 | 高 — 草原核误判导致错误引爆策略 | 种子 6s 生命周期 |

元素附着的检测流程：
```
角色施加元素 → 检测敌人头顶元素图标 (16×16px) →
  元素附着分类器 (7+1 类) → 确认附着元素类型 →
    → 查询元素反应决策表 (预定义反应优先级) →
      → 选择最优后续元素攻击 → 生成对应的角色切换 + 技能释放 Intent
```

## 附录 D：多人联机模式的精度退化容忍

联机模式下新增的感知挑战和精度降级策略。

| 联机特有挑战 | 对感知的影响 | 精度退化幅度 | 缓解策略 |
|---|---|---|---|
| 其他玩家角色可见 (最多 3 人) | 增加 3 个类敌人但非敌人的移动实体；YOLO 可能误判为敌人 | 敌人检测 mAP 下降 5-10% | 己方角色模型白名单过滤 (基于模型纹理特征而非检测) |
| 网络延迟导致的位置抖动 | 其他玩家和敌人的位置不稳定，跟踪器 ID Switch 增加 | 跟踪 MOTA 下降 10-15% | 增大 BoT-SORT 关联门限；降低对友方位置精度要求 |
| 特效叠加 (4 人同时释放技能) | 画面遮挡严重，所有检测目标置信度下降 | 全局检测置信度下降 15-25% | 基于时序的信息补全 (盲区预测)；暂停高精度操作等待特效消散 |
| 联机 Boss 血量缩放 | Boss 血条视觉不变但实际血量增加 | 无影响 (HP 百分比检测不变) | 无需特殊处理 |
| 其他玩家触发交互 (开机关/对话) | 交互提示可能突然出现/消失 | 交互检测可用性判断延迟增加 200ms | 轮询式交互检测 (不依赖事件触发) |
| 聊天消息 / 表情弹窗 | 新增 UI 遮挡元素 | UI 层级检测复杂度增加 | 聊天区域固定占屏下部 20%，可预设遮挡掩码 |

联机模式下的整体配置调整：
- Perception 频率上限：降至正常的 80% (为网络数据接收留 CPU)
- 操作延迟容忍：放宽至 1.5 倍 (网络延迟不可控)
- 安全关键检测 (氧气条/技能预警)：精度要求不变
- 非安全关键检测：置信度阈值统一降低 0.05
