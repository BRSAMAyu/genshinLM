- **中间关键状态:**

  - T+0:42: 蒙德城到达，城内传送点解锁
  - T+0:55: 风之翼获得，骑士团任务激活

### 异常中断与恢复

| 异常类型 | 检测条件 | 恢复策略 | 预计恢复耗时 |
|---|---|---|---|
| 教学提示卡死 | 同一UI提示保持 > 60秒无变化 | 截图分析提示内容 → 按提示要求的按键 → 若仍无响应，按Esc再重新进入 | 30秒 |
| 战斗死亡 | HP归零 + 死亡画面出现 | 等待自动复活 → 检查复活后位置 → 重新导航到目标点 | 60秒 |
| 游泳溺水 | 体力耗尽 + 溺水动画 | 等待自动复活在岸边 → 查找替代路径 (避免水域) | 45秒 |
| 攀爬坠落 | 高度跌落 + 摔伤HP变化 | 检查HP → 若HP过低先使用食物恢复 → 重新调整攀爬路线 | 30秒 |
| 导航卡住 | 角色位置 > 30秒无明显变化 | 检查周围障碍物 → 尝试绕行 → 若仍失败，打开地图传送最近锚点重新来 | 40秒 |
| Boss战失败 | 全队HP归零 + "挑战失败"弹窗 | 点击"重新挑战" → 分析失败原因 (DPS不足? 机制失误?) → 调整策略重试 | 120秒 / 含Boss战重打 |
| 对话分支选错 | 对话选项误选非推荐项 | 多数非关键分支不影响主线推进；若影响则检测任务日志是否更新 → 若未更新则对话未完成需重进 | 20秒 |

### 关键交互节点

1. **滑翔教学 (T+0:15):** 最易出错节点——过早/过晚展开风之翼导致坠落死亡。保障措施：检测"空中状态"标记后延时 0.5 秒再展开风之翼；若检测到急速下坠则立即展开。
2. **风之翼正式获得 (T+0:55):** 对话流程中的关键物品获取。保障措施：对话完成后校验背包中是否存在风之翼物品ID，若未获得则检查任务日志是否标记完成。
3. **四风神庙平台跳跃 (T+1:10):** 多个连续平台跳跃，跌落风险高。保障措施：每个平台落地后确认站稳 (检测"地面状态") 再跳下一个；若跌落则从上一个平台重试。
4. **特瓦林空中追击 (T+1:40):** 瞄准射击在移动中执行，操作精度要求高。保障措施：提前锁定目标凝块 (视觉追踪)，射击前确认准星与目标重合度 > 80%；若连续3次射失则降低灵敏度重试。
5. **特瓦林平台近战 (T+1:48):** Boss机制型战斗，需要特定顺序操作。保障措施：检测Boss当前姿态 (爪击/龙息/虚弱)，仅在虚弱状态下执行攀爬+核心攻击；若DPS不足以一轮击杀则循环直到击败。

### 状态管理

- **进入状态:** 任意安全位置，记录 `{初始位置, 初始树脂量, 初始原石量, 委托完成数(通常0/4), 当前队伍配置}`
- **中间关键状态:**
  - T+0:15: 委托列表已读取
  - T+1:30 ~ T+10:00: 逐个委托执行中 (1/4 → 2/4 → 3/4 → 4/4)
  - T+10:15: 委托完成奖励已领取
  - T+10:50 ~ T+13:00: 树脂消耗迭代中
  - T+14:00: 纪行奖励已领取
- **退出状态:** 回到初始位置附近，树脂耗尽或不足20，委托完成奖励已领取，纪行已领

| 异常类型 | 检测条件 | 恢复策略 | 预计恢复耗时 |
|---|---|---|---|

| 用户中断请求 | 用户说"停下" / "暂停" / "取消" | 完成当前原子操作后安全停止 → 保存当前进度状态 → 汇报已完成内容 | 5-30秒 |

### 关键交互节点

1. **委托类型识别 (T+0:30):** 4个委托中可能存在无法自动完成的类型 (如限时配送、特殊解谜)。保障措施：读取委托名称后与已知可行委托类型列表匹配；不可行类型标记为跳过并记录原因。
2. **凯瑟琳交互 (T+10:15):** 频繁对话场景，UI层级变化多。保障措施：每一步检查对话选项的文本；用固定选项文本 ("领取「每日委托」奖励") 匹配而非位置匹配。
3. **树脂消耗决策 (T+10:30 - T+13:00):** 需要智能决定消耗方式 (秘境 vs Boss vs 地脉花)。保障措施：按优先级排序——有浓缩树脂优先用浓缩 → 优先打当前UP角色需要材料的秘境 → 剩余用世界Boss消耗。
4. **队伍切换 (如有需要):** 涉及多层UI操作。保障措施：打开队伍配置前截图确认当前队伍；切换后再次截图确认队伍已变更到位。

### 关键交互节点

1. **圣遗物筛选与对比 (T+19:00):** 五个位置 × 数百件圣遗物 = 组合爆炸。保障措施：使用规则引擎而非穷举——主属性必须匹配角色定位 (如雷电将军优先充能沙) → 套装优先4件套 → 副属性排序 (双暴 > 充能 > 攻击) → 每个位置选出Top3后组合验证套装效果。
2. **Boss材料循环 (T+2:00 - T+4:30):** 同一Boss可能需要多次击杀 (3-5次)，中间等待刷新。保障措施：树脂充足时循环击杀 → 树脂耗尽则标记剩余缺口；世界Boss刷新约3分钟，期间可传送采集周边特产再回来。
3. **圣遗物强化狗粮管理 (T+21:00):** 强化到+20需要大量狗粮且可能不够。保障措施：优先使用3星及以下圣遗物 → 4星圣遗物仅当确定废弃时才用；若到+16已无狗粮且无明显提升价值则停止。
4. **天赋书日程匹配 (T+24:30):** 天赋书秘境按周循环，需确保当日可进。保障措施：读取系统日期 → 匹配天赋书秘境开放表 → 若当日不开放则跳过天赋升级阶段 → 记录"下次在周X执行"。
5. **最终面板验证 (T+28:00):** 必须确认所有操作真正生效——圣遗物装备上去了吗？武器换了吗？天赋等级变了吗？保障措施：重新打开角色界面 → 逐项截图对比初始快照 → 数值变化 > 0 视为有效。

- **世界Boss**: 击败后等待约3分钟刷新。Agent 应在刷新间隔期间传送做其他事 (采集周边特产/清剿周边精英怪)，然后传送回来。这要求Agent维护"待返回Boss位置"的状态。
- **精英怪路线**: 每种精英怪材料在各地图有固定路线 (如刀镡→稻妻各岛武士营地、浮游核→须弥沙漠)。Agent 需内置最高效的精英怪清剿路线 (200精英怪/天的上限检测)。
- **天赋书秘境**: 按周循环——蒙德/璃月(周一/四 自由/繁荣/勤劳)、璃月/稻妻(周二/五 抗争/浮世/风雅)、稻妻/须弥(周三/六 诗文/黄金/天光)。周日全部开放。Agent 需读取系统星期几来匹配。

### 分批养成与跨日延续

当一次会话无法完成全部养成时 (树脂不足/特产枯竭/秘境今日不开)：

1. 按优先级执行当前可行的步骤
2. 记录"未完成清单"写入持久化状态: `{角色名, 待办项, 所需材料, 缺口数量, 预计下次可执行日期}`
3. 下次用户说"继续培养XX"时，先读取未完成清单再检查新状态
4. 跨日养成需重新检查树脂量 (已回满160) 和秘境开放日

### 关键交互节点

1. **任务目标类型识别 (T+0:15):** 任务描述文本的OCR和解析是最容易出错的环节——任务描述可能很长且包含多个子目标。保障措施：优先解析任务日志中的"目标"字段 (结构化文本) → 关键词匹配 (击败/寻找/与...对话/调查/收集) → 定位地图标记 → 三重确认 (任务文本 + 地图标记 + 当前场景) 一致才开始导航。
2. **过场动画判断 (T+10:00):** 过场动画期间UI消失，不能做任何操作 (除了跳过)。保障措施：检测画面风格突变 (全屏/宽银幕比例变化 + HUD消失) → 等待300ms确认不是瞬时的特效切换 → 然后查找"跳过"按钮 → 若存在则点击跳过。
3. **Boss机制学习 (T+23:00 - T+26:00):** 剧情Boss通常有特殊机制 (护盾/无敌阶段/需要特定元素反应)。保障措施：第一阶段以"观察"为主——回避攻击、分析动作模式、识别弱点元素 → 第二阶段才全力输出；若第一次失败，从失败画面提取提示信息 (如"使用XX元素攻击弱点")。
4. **迷宫路径记忆 (T+18:00 - T+23:00):** 遗迹类型迷宫可能有多层+机关连锁。保障措施：维护已访问房间的特征集合 (房间形状、机关类型、敌人配置) → 避免重复进入同一房间 → 机关状态变更时更新全局状态 → 使用左手/右手法则作为兜底策略。
5. **任务链自动衔接 (T+31:00):** 完成任务后可能自动接取下一段，需无缝切换。保障措施：任务完成弹窗消失后立即检查任务日志 → 若出现新任务且为同一章节 → 自动开始追踪 → 无需用户再输入"继续"。

### 任务对话分支处理策略

主线任务中的对话分支通常不影响最终结果 (殊途同归)，但个别分支可能影响后续任务细节。Agent 的处理策略：

1. **优先选择推荐选项:** 若任务日志中有提示 (如"与XX对话获取线索")，优先选择对应选项
2. **选择与当前任务目标一致的选项:** 如目标是"说服XX"，选择最温和的对话选项
3. **避免选择带有警告标记的选项:** 如"这将导致..."的提示文本
4. **记录所有分支选择:** 写入任务日志，支持事后回溯

## 长程场景 5：迷路/卡住恢复链

**触发条件:** Agent在执行任何场景时检测到异常停滞——重复操作无进展、连续战斗失败、UI识别超时、或收到用户"你卡住了"的提示。
**预计总耗时:** 30-120秒 (视异常类型而定)
**涉及场景类型:** 全部 (通用恢复)
**前置条件:** 处于任意活跃场景中

### 阶段一：异常检测 (持续监控)

Agent在所有长程场景中持续监控以下指标，任一指标触发阈值即进入异常状态：

| 监控指标 | 检测方式 | 正常范围 | 异常阈值 | 异常类型 |
|---|---|---|---|---|
| 位置变化率 | 每5秒计算一次位置位移量 | > 2m/5s | < 0.5m/5s 持续30秒 | 导航卡住 / 碰撞卡墙 |
| 战斗尝试计数 | 同一战斗场景进入次数 | ≤ 2次 | 第3次进入同一战斗 | 战斗失败循环 |
| UI操作超时 | UI操作发出到结果检测的时间 | < 5秒 | > 15秒无结果 | UI卡死 / 识别失败 |
| 画面重复度 | 每10秒截图与30秒前截图的结构相似度 | 有差异 (活动场景) | SSIM > 0.95 持续60秒 | 画面冻结 / 无新内容加载 |
| 操作无效果 | 同一操作 (如按键) 重复发出但状态无变化 | 操作后状态变化 | 同一操作发出5次状态不变 | 操作失效 / 输入被拦截 |
| 任务进度停滞 | 任务日志目标描述未更新 | 任务目标定期变更 | 同一目标描述保持 > 5分钟 | 任务卡关 / 触发条件未满足 |
| HP持续危险 | 队伍HP检查 | > 30% | < 20% 且持续下降 | 即将全灭 |
| 用户显式中断 | 用户说出"停"/"卡住了"/"你在干嘛" | — | 检测到关键词 | 用户主动中断 |

### 恢复策略决策树

```
异常类型 ──→ 恢复策略

感知异常:
  ├── 目标未检测到 (置信度低) → 策略1-重试: 调整视角重识别
  ├── 目标检测错误 (类型/位置错) → 策略1-重试: 切换检测模型/降低阈值
  └── 环境变化 (光照/天气) → 策略1-重试: 等待环境恢复或传送重载

导航异常:
  ├── 卡墙/碰撞 → 策略1-重试: 后退+绕行
  ├── 路径不存在 → 策略2-绕过: 切换传送点接近
  ├── 目标在空中/地下 → 策略2-绕过: 查找多层入口
  └── 地形复杂 (水域/悬崖) → 策略2-绕过: 寻找安全路线

操作异常:
  ├── 输入无响应 → 策略1-重试: 释放所有按键再重新发送
  ├── 操作精度不足 → 策略1-重试: 降低操作速度/调整参数
  ├── UI元素偏移 → 策略1-重试: 重新定位UI锚点
  └── 连续误操作积累 → 策略2-绕过: 传送重置位置

逻辑异常:
  ├── 任务触发条件未满足 → 策略1-重试: 检查+重做前置步骤
  ├── 任务描述理解错误 → 策略1-重试: 重新OCR+分析任务文本
  ├── 隐藏机制/条件 → 策略2-绕过: 尝试不同条件 (时间/元素)
  └── 任务BUG/设计限制 → 策略3-切换目标: 暂停+切换

紧急异常:
  ├── 画面黑屏/冻结 → 策略5-紧急安全: 等待5秒→若不变→紧急停止
  ├── 连续崩溃 (5次+) → 策略5-紧急安全: 保存日志→停止
  ├── HP归零循环 → 策略4-请求协助: 告知用户战斗配置不足
  └── 无法与游戏交互 (>2分钟) → 策略5-紧急安全: 释放输入→请求协助
```

### 状态管理

- **进入状态:** 异常触发时刻的完整状态快照：`{异常类型, 触发指标, 当前场景, 场景进度, 队伍状态, 画面截图, 操作日志(buffer)}`
- **中间关键状态:**
  - T+0:02: 状态快照已采集
  - T+0:09: 异常原因已诊断
  - T+0:10: 恢复策略已选定
  - T+0:12 ~ T+0:50: 恢复策略执行中
  - T+1:30: 恢复验证完成或升级到更高层策略
- **退出状态:**
  - 成功路径: 异常解除，原始任务继续执行，恢复日志已记录
  - 半成功路径: 原始任务暂不可行，切换到备选任务，原任务进度已保存
  - 失败路径: 自动恢复失败，用户已获通知，输入已安全释放

### 关键交互节点

1. **异常检测的灵敏度平衡 (持续监控):** 阈值设得太低会导致频繁误报 (如正常加载被误判为卡死)，设得太高会导致真正的问题迟迟不被发现。保障措施：使用双阈值——轻阈值触发"观察模式" (暂不干预，加强监控)、重阈值触发"恢复模式"；位置变化率用EWMA平滑，避免瞬时波动触发。
2. **状态快照的完整性 (T+0:02):** 如果异常发生在截图/日志记录本身就失败的时候，快照收集可能也不可用。保障措施：维护一个5秒滚动缓冲区——始终保留最近5秒内的画面帧和操作记录；触发恢复时直接从缓冲区读取。
3. **恢复策略的升级路径 (T+0:10 - T+0:50):** 策略不能无限重试——需要明确的升级路径和停止条件。保障措施：每层策略最多尝试2-3次 → 失败则升级到下一层 → 最终到达"请求协助"或"紧急停止"；全程计时，总恢复时间超过120秒则强制请求协助。
4. **用户沟通的清晰度 (T+0:50):** 请求协助时不能让用户困惑。保障措施：求助信息必须包含 (1) 当前在做什么, (2) 遇到了什么问题, (3) Agent已经尝试了什么, (4) 用户可以做哪1-2件事来帮助。例如："我在执行'调查风龙废墟'任务时卡住了——已经到达标记点但未触发任务对话。我已尝试重新接近、调整视角、重新登录任务。请帮我确认是否需要先与温迪对话？或者手动触发一下？"
5. **恢复后的上下文恢复 (T+1:30):** 恢复完成后无缝衔接回原始任务是最难的——恢复过程中可能改变了视角、位置、甚至任务状态。保障措施：恢复完成后先做一次"上下文重建"——检查任务日志确认目标未变 → 重新定位 → 验证周围环境与中断前一致 → 然后才继续执行下一步。

### 恢复场景示例

以下是三个具体的恢复案例，展示异常检测 → 诊断 → 策略选择 → 恢复的完整流程：

#### 示例 A：日常委托中导航卡墙

```
场景：执行第3个日常委托，导航到委托标记点途中
触发：位置变化率 < 0.5m/5s 持续30秒 (EWMA平滑后)
快照：
  - 位置：(2341, -876)，靠近悬崖边的一块大石头
  - 目标：委托标记点距离约47m，在石头后方
  - 画面：角色面对一面岩壁，无法前进
诊断：
  - 感知：目标在画面中不可见 (被石头遮挡)，置信度N/A
  - 操作：WASD移动操作已发送但位置无变化 → 碰撞体阻挡
  - 结论：导航异常 - 碰撞卡墙
策略选择：策略1-重试 (导航异常)
执行：
  1. 释放W键 → 后退3步
  2. 左移5步绕过石头
  3. 重新计算路径 (A*绕行)
  4. 沿新路径前进
验证：位置变化率恢复到 > 2m/5s → 恢复成功
耗时：约8秒
```

#### 示例 B：角色培养中Boss战失败

## 场景交叉执行矩阵

实际使用中，用户可能在执行一个长程场景时切换到另一个。以下是所有合法的场景交叉路径及其处理方式：

| 当前场景 | 切换到 | 触发条件 | 处理方式 |
|---|---|---|---|
| 日常会话 | 角色培养 | 用户在途中说"帮我培养XX" | 日常完成后 (或用户取消日常后) 进入培养流程；不建议中途切换以免树脂消耗逻辑冲突 |
| 日常会话 | 主线任务 | 用户说"别做日常了，推主线" | 安全停止当前委托 → 保存委托进度 → 切换到主线场景；树脂消耗阶段可继续 (共享树脂) |
| 日常会话 | 恢复链 | 日常执行中遇到异常 | 优先用恢复链处理 → 恢复后继续日常 → 若不可恢复则暂停日常 |
| 角色培养 | 日常会话 | 培养中发现树脂不够且当日委托未做 | 先完成日常委托 (获取原石+经验) → 领取奖励 → 用获得的资源继续培养 |
| 角色培养 | 主线任务 | 用户说"先推主线吧" | 暂停培养 → 保存未完成清单 → 切换到主线；主线中获得的新材料可更新培养进度 |
| 主线任务 | 角色培养 | 主线推进中遇到等级/战力不足 | 暂停主线 → 对当前队伍中的角色做紧急培养 (升级/装备) → 培养完成后继续主线 |
| 主线任务 | 日常会话 | 主线进行到需要等待/无法继续 | 记录主线进度 → 切换到日常完成当日委托 → 回来继续主线 |
| 任意场景 | 恢复链 | 异常检测触发 | 暂停当前场景 → 进入恢复链 → 恢复后回到当前场景 |
| 任意场景 | 用户主动切换 | 用户说"停/取消/换一个" | 安全停止当前原子操作 → 保存进度 → 询问用户需求 → 进入新场景 |

### 场景状态持久化接口

每个长程场景必须支持以下接口，以支持场景切换：

```
# 暂停当前场景 (保存所有中间状态)
scene.pause() -> SceneCheckpoint:
    - scene_type: str           # 场景类型标识
    - progress_pct: float       # 完成百分比 0.0-1.0
    - checkpoint_data: dict     # 场景特定的中间状态
    - timestamp: float          # perf_counter 时间戳
    - game_state: dict          # 游戏侧状态快照 (位置/HP/树脂/任务)

# 从检查点恢复
scene.resume(checkpoint: SceneCheckpoint) -> bool:
    - 验证游戏状态是否与检查点兼容
    - 恢复中间状态
    - 从断点继续执行

# 获取场景摘要 (用于汇报/跨场景通信)
scene.summary() -> SceneSummary:
    - completed_steps: list     # 已完成的步骤
    - pending_steps: list       # 待完成的步骤
    - resources_used: dict      # 已消耗的资源 (树脂/摩拉/经验书等)
    - resources_gained: dict    # 获得的资源
```

## 跨场景通用规范

### 能力ID命名规范

所有原子能力使用 `{领域}_{子领域}_{动作}` 格式：

| 领域 | 前缀 | 示例 |
|---|---|---|
| 感知 | PERCEPTION_ / VISION_ | VISION_CHEST_DETECT, PERCEPTION_DISTANCE |
| 导航 | NAV_ | NAV_TELEPORT, NAV_PATH_FIND |
| 移动 | MOVE_ | MOVE_WALK, MOVE_CLIMB |
| 战斗 | COMBAT_ | COMBAT_BASIC_ATTACK, COMBAT_SHIELD_BREAK |
| 探索 | EXPLORE_ | EXPLORE_COLLECT, EXPLORE_INVESTIGATE |
| 解谜 | PUZZLE_ | PUZZLE_ELEMENTAL_MONUMENT |
| UI操作 | UI_ | UI_DIALOG_ADVANCE, UI_MAP_OPEN |
| 任务 | TASK_ | TASK_STATE_READ, TASK_TRACK |
| 状态管理 | STATE_ | STATE_SNAPSHOT_COMPARE, STATE_HP_CHECK |
| 规划 | PLANNER_ | PLANNER_GOAL_SET, PLANNER_ROUTE_OPTIMIZE |
| 日志 | LOG_ | LOG_EXPORT, LOG_RECOVERY_RECORD |
| 恢复 | RECOVERY_ | RECOVERY_POLICY_SELECT |

### 场景转换条件检测方式

所有场景转换条件需通过以下方式之一确认：

1. **视觉检测 (V):** 截图 + 目标检测/模板匹配/OCR → 对应 `VISION_*` 能力
2. **状态检测 (S):** StateBus中读取 HUD/任务/HP 等状态 → 对应 `STATE_*` 能力
3. **UI检测 (U):** 检测UI元素的出现/消失/变化 → 对应 `UI_*` 能力
4. **事件检测 (E):** 监听游戏内事件 (成就弹窗、奖励弹窗) → `EVENT_*` 能力
5. **计时器 (T):** 操作后等待指定时间 (仅用于加载/动画等待，不可用于核心逻辑) → `TIMER_WAIT`

每个场景转换条件必须标注检测方式，例如：`(V+S) 敌人血条消失 + 战斗BGM停止`

### 失败恢复通用原则

1. **任何原子操作不超过3次重试。** 3次失败后必须升级到绕过/切换/求助。
2. **每个状态变更后必须验证。** 操作完成 ≠ 操作生效。操作完成后必须检测预期的状态变化是否发生。
3. **单调递增时钟作为所有超时判断的基础。** `time.perf_counter()`，禁止 `time.time()`。
4. **不假设"操作一定成功"。** 默认操作可能失败，通过验证发现失败并恢复。
5. **所有关键操作可安全中断。** 断开HTTP请求/释放按键/停止移动 → 在收到用户中断或遇到紧急异常时安全停下。
6. **保持上下文可追溯。** 所有异常和恢复过程写入结构化日志，支持事后分析和改进。
