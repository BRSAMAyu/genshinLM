## 第一章：自主等级体系

### 1.1 等级定义

Agent 自主行为被严格划分为四个等级，由低到高递增。每个等级定义 Agent
可执行的操作范围、所需用户确认程度以及行为边界。

#### Level 0 -- 纯手动（Manual）

**核心理念：** Agent 是被动智能顾问，仅展示信息与建议，不执行任何游戏操作。

**Agent 行为：**
- 信息展示：在覆盖层显示游戏状态摘要（角色状态、任务进度、资源余量）
- 策略建议：推荐角色搭配、技能释放顺序、探索路线
- 状态监控：监测树脂溢出风险、委托剩余时间、活动截止倒计时
- 知识查询：回答游戏机制提问（元素反应、圣遗物属性、Boss 弱点）

**绝对禁止：** 执行任何键盘/鼠标输入、修改游戏内状态、自主导航 UI 菜单。

**适用场景：** 用户首次使用时的默认模式；用户要求"只看不操作"；感知模块不可靠时；高难度内容（深渊/联机）时自动降级。

---

#### Level 1 -- 辅助模式（Assisted）

**核心理念：** Agent 可自主执行低风险操作，高风险操作需用户确认。

**低风险操作：**

| 类别 | 操作 | 风险说明 |
|------|------|----------|
| 日常委托 | 自动接受/完成每日委托 | 奖励固定，无失败惩罚 |
| 树脂消耗 | 按预设优先级消耗树脂 | 使用浓缩树脂，仅打已配置副本 |
| UI 导航 | 打开背包、角色面板、地图 | 仅导航，不做修改 |
| 材料采集 | 自主采集大世界材料 | 仅采集，不出售/合成 |
| 派遣回收 | 回收探索派遣奖励 | 重新派遣需确认 |
| 领取奖励 | 领取邮件、纪行、活动奖励 | 仅领取，不消耗 |

**高风险操作（需确认）：**

| 类别 | 操作 | 确认要求 |
|------|------|----------|
| 祈愿 | 消耗原石/纠缠之缘的操作 | 显式确认 + 原石数量展示 |
| Boss 战 | 进入周本/世界 Boss 战斗 | 确认角色配置和食物准备 |
| 主线推进 | 推进主线/传说/邀约任务 | 确认是否继续（不可逆） |
| 圣遗物强化 | 消耗强化材料强化圣遗物 | 展示预期属性 + 确认 |
| 商店购买 | 购买任何物品 | 价格展示 + 余额预览 |
| 角色培养 | 升级角色/天赋/武器 | 资源消耗预览 |

**用户确认界面：**

```
+-----------------------------------------------+
|  [Agent] 请求确认                               |
|                                                |
|  操作：消耗 160 树脂 x 秘境「绝缘之旗印」        |
|  预计获得：圣遗物 x 5~7、冒险阅历 x 200          |
|  当前树脂：184/200                              |
|                                                |
|  [确认执行]     [拒绝]     [10s 后自动确认]      |
+-----------------------------------------------+
```

- 弹窗提示操作详情与资源预览
- 倒计时自动确认（默认 10s，可配置）
- 一键拒绝（点击或 Esc）
- 可配置白名单免除确认

---

#### Level 2 -- 监督模式（Supervised）

**核心理念：** Agent 完全自主执行，用户可随时通过热键暂停或接管。

**Agent 权限：** 自主执行所有低风险和高风险操作；自主导航、战斗、采集、任务推进；自主进行 UI 操作和菜单交互。

**用户保留权利：** 随时按 F8 暂停；随时通过鼠标/键盘接管；要求 Agent 在特定步骤等待；查看并修改任务计划。

**关键节点通知（必须通知）：**

| 事件类型 | 通知内容 | 用户操作 |
|----------|----------|----------|
| Boss 战开始 | Boss 名称 + 当前队伍 | 可暂停或继续 |
| 祈愿结果 | 星级结果摘要 | 展示结果 |
| 任务完成 | 任务名 + 获得奖励 | 确认继续 |
| 异常检测 | 异常状态描述 | 选择处理方式 |
| 资源耗尽 | 树脂/原石不足 | 选择下一步 |

用户接管后 Agent 立即进入 Level 0 待命，保留任务上下文，可随时按 F8 恢复。

---

#### Level 3 -- 全自主（Autonomous）

**核心理念：** Agent 完全自主运行，仅异常时通知。适用于长时间挂机。

**适用场景：** 日常委托全流程（15-30 分钟）；树脂消耗循环；大世界材料采集；探索派遣回收。

**异常通知条件（仅以下情况打扰）：**

| 条件 | 阈值 | 级别 |
|------|------|------|
| 连续失败 | 同一操作连续失败 3 次 | Critical |
| 资源不足 | 树脂耗尽/食物用完/原石不足 | Warning |
| 非预期状态 | 角色死亡/任务无法推进/UI 卡住 | Critical |
| 时间超限 | 达到会话时间预算 | Warning |
| 安全面板触发 | 窗口失焦/检测到弹窗/游戏崩溃 | Emergency |

**安全底线（即使 L3 也不可逾越）：** 原石消耗不超过会话上限；不执行未授权操作；用户热键随时可中断；强制休息间隔（每 60 分钟暂停 5 分钟）。

---

### 1.2 等级切换条件

| 当前 | 目标 | 触发方式 | 需确认 | 延迟 |
|------|------|----------|--------|------|
| L0 | L1 | 用户指令 | 是（首次） | 即时 |
| L0 | L2 | 用户指令 | 是（首次） | 即时 |
| L0 | L3 | 用户指令 | 是（首次） | 3s 确认 |
| L1 | L0 | 用户指令/Agent 降级 | 否 | 即时 |
| L1 | L2 | 用户指令 | 是 | 即时 |
| L1 | L3 | 用户指令 | 是 | 3s 确认 |
| L2 | L0 | 用户接管/Agent 降级 | 否 | 即时 |
| L2 | L1 | Agent 遇无法处理场景 | 否（自动） | 即时 |
| L2 | L3 | 用户指令+确认 | 是 | 3s 确认 |
| L3 | L0 | 紧急接管 | 否 | 即时 |
| L3 | L1 | 异常检测自动降级 | 否 | 即时 |
| L3 | L2 | 用户暂停/时间告警 | 否 | 即时 |

**自动降级触发：** 感知置信度 < 0.5 → L2/L3 降至 L1；同一任务连续失败 3 次 → 降至 L1；检测到解谜 → L2 降至 L1；窗口失焦恢复后 → L3 降至 L2；用户输入检测 → 任意降至 L0。

**自动升级：** Agent 不可自动升级。所有升级必须由用户显式触发。

### 1.3 用户通知策略

| 等级 | 通知频率 | 通知方式 | 免打扰 |
|------|----------|----------|--------|
| L0 | 仅用户主动查询 | 覆盖层文字 | 始终免打扰 |
| L1 | 低风险不通知；高风险弹窗 | 弹窗+声音 | 战斗中不弹窗 |
| L2 | 关键节点通知 | 覆盖层+声音 | Boss 战延迟通知 |
| L3 | 仅异常通知 | 覆盖层+声音+可选推送 | 无免打扰 |

## 第二章：控制权切换协议

所有切换保证四性：安全性（不产生危险操作）、原子性（完全成功或回滚）、一致性（双方状态一致）、可追溯（所有切换被记录）。

### 2.1 用户到Agent交接

#### 交接检查清单

Agent 接受控制权前必须逐项验证：

```
[ ] 游戏窗口已获得焦点
[ ] 游戏处于可操作状态（非加载/非过场动画）
[ ] 感知模块正常（帧率 >= 15fps，延迟 < 200ms）
[ ] 当前场景可识别（UI 状态置信度 >= 0.7）
[ ] 目标任务已明确、自主等级已确认
[ ] 资源预算已设定（树脂、原石、时间）
[ ] SafeWindowInputBackend 已就绪、热键已注册
```

任何一项不满足，Agent 拒绝交接并说明原因。

#### 交接状态同步

1. **视觉快照**：截取画面，识别 UI 状态（主界面/地图/背包/战斗/对话）
2. **角色状态**：队伍配置、血量/能量、Buff
3. **任务状态**：进行中任务及进度
4. **资源状态**：树脂余量、原石数量、食物库存
5. **环境状态**：当前位置、游戏内时间

存入 StateBus：`current_goal` <- 用户指令；`current_mode` <- IDLE；`latest_observation` <- 视觉快照。

#### 交接超时

| 阶段 | 超时 | 超时行为 |
|------|------|----------|
| 检查清单 | 30s | 告知未通过项，请求修正 |
| 状态同步 | 60s | 以部分状态继续 |
| 等待确认 | 120s | 取消交接 |

### 2.2 Agent到用户归还

#### 主动归还条件

| 条件 | 优先级 | 处理 |
|------|--------|------|
| 任务完成 | 普通 | 整理状态后归还 |
| 无法处理的场景 | 高 | 立即停止，说明原因 |
| 安全面板触发 | 最高 | 立即停止，释放所有输入 |
| 资源预算耗尽 | 普通 | 完成当前步骤后归还 |
| 感知模块异常 | 最高 | 立即停止，释放所有输入 |
| 游戏崩溃 | 最高 | 等待恢复后通知用户 |

#### 归还前状态整理

1. 释放所有 InputLease（`InputWorker.release_all`）
2. 等待当前动作完成（最多 2s）
3. 角色移到安全位置
4. 关闭所有 UI 面板
5. 设置 `StateBus.current_mode = IDLE`
6. 触发归还通知

#### 归还通知

向用户展示上下文摘要：

```
+-------------------------------------------------------+
|  [Agent] 控制权归还                                      |
|                                                        |
|  原因：所有日常委托已完成                                  |
|                                                        |
|  执行摘要：                                              |
|  - 完成 4 个每日委托（用时 12 分钟）                       |
|  - 消耗 120 树脂（秘境 x 2）                             |
|  - 领取凯瑟琳奖励 + 60 原石                               |
|                                                        |
|  当前状态：                                              |
|  - 角色位置：蒙德城凯瑟琳面前                              |
|  - 树脂：80/200                                         |
|  - 原石：3,240（今日消耗 60）                             |
|                                                        |
|  建议下一步：                                             |
|  - 树脂将在 3 小时后溢出，建议稍后继续消耗                  |
|                                                        |
|  [好的]     [继续执行]     [查看详细日志]                  |
+-------------------------------------------------------+
```

### 2.3 紧急接管

#### 触发方式

| 方式 | 实现机制 | 响应时间 |
|------|----------|----------|
| F9 热键 | 全局键盘钩子 | < 50ms |
| 鼠标大幅移动 | MouseDeltaMonitor > 200px/s | < 100ms |
| 任意键盘输入 | KeyboardMonitor | < 100ms |
| Ctrl+C | SIGINT 信号 | < 50ms |
| 窗口切换 | FocusState 监听 | < 200ms |

#### Agent 检测到用户输入后的行为

1. 立即执行 `InputWorker.release_all()`
2. 设置 ModeArbiter 为 `EMERGENCY_STOPPED`（终端模式，仅自身可转换到自身）
3. 发布 P0 Interrupt（`priority=0, requires_input_release=True`）
4. Agent 进入 Level 0 待命
5. 200ms 后通知用户"已释放控制权"

关键：`EMERGENCY_STOPPED` 不会自动恢复，用户必须显式按 F8 重启。

#### 接管后状态恢复

Agent 持续截图但不执行操作；对比接管前后画面差异；推断用户意图；覆盖层显示简短摘要；用户重新请求时基于最新状态同步。

---

### 2.4 切换防抖

**防抖参数：** 最小切换间隔 2s；30s 窗口内最多 5 次切换；超限后锁定 10s。

**上下文保存：**

```python
@dataclass(slots=True)
class HandoverContext:
    timestamp: float
    direction: str              # "user_to_agent" | "agent_to_user"
    autonomous_level: int       # 0-3
    current_goal: str
    game_state_summary: str
    pending_actions: list[str]
    resource_snapshot: dict
    observation_version: int    # StateBus 版本号
```

保存到 StateBus 动态 Slot，确保重新激活时可恢复。

**切换日志：** 所有切换事件记录到 Telemetry JSONL 日志：

```json
{
  "event": "handover",
  "timestamp": 1700000000.123,
  "direction": "user_to_agent",
  "level_from": 0,
  "level_to": 2,
  "trigger": "user_command",
  "context_saved": true,
  "checklist_passed": true,
  "latency_ms": 45
}
```

## 第三章：安全边界与护栏

安全边界在代码层面硬编码，不通过配置文件可修改。

### 3.1 输入安全

| 规则 | 实现方式 | 验证频率 |
|------|----------|----------|
| 只操作游戏窗口内输入 | SafeWindowInputBackend 验证窗口标题+进程名 | 每次输入前 |
| 禁止系统级输入 | Win32 API 仅 SendInput 到目标窗口 | 代码层面 |
| 窗口失焦立即释放 | FocusState 检查，focus=False 触发 P0 Interrupt | 每帧 |
| 异常立即释放 | Deadman Switch: lease 超时/线程异常/P0 中断 | 持续 |

**InputLease 安全规则：** 过期时间最大 5s；P0/P1 中断立即吊销所有活跃 Lease；同一时间仅一个 Owner；释放操作幂等。

**紧急停止：**

| 触发 | 响应链 | 恢复 |
|------|--------|------|
| F9 | release_all -> EMERGENCY_STOPPED | 用户手动重启 |
| Ctrl+C | shutdown_flag -> release_all | 重启 Agent |
| Watchdog 超时 | P1 Interrupt -> release_all | 自动或等待 |
| 线程异常 | Deadman Switch -> release_all | 取决于异常 |

### 3.2 资源保护

**原石消耗：** 单次会话上限 1600（默认）；每日上限 3200；祈愿无论等级均需确认；超预算禁止消耗。

**检查流程：**

```
原石消耗检查流程
================
1. 操作前检查当前消耗累计
2. 如果 本次消耗 + 已消耗 > 会话上限 → 拒绝操作
3. 如果 本次消耗 + 今日已消耗 > 每日上限 → 拒绝操作
4. 通过检查 → 弹窗确认（展示余额和消耗后余额）
5. 用户确认 → 执行 → 更新消耗计数
6. 用户拒绝 → 跳过操作 → 记录日志
```

**树脂消耗：** 需匹配用户设定优先级策略；浓缩树脂优先；树脂 >= 150 时提醒。

**物品保护：** 禁止出售 4 星以上物品；禁止出售武器；禁止分解已装备圣遗物；禁止删除角色。全部 L0-L3 硬编码。

### 3.3 行为边界

**绝对禁止（所有等级）：** 进入联机模式；修改游戏设置；删除角色/物品；与陌生玩家交互；使用兑换码；购买付费内容；参与 PVP；未经授权修改队伍配置。

**条件允许：** 队伍配置修改（L1+用户指定）；角色/武器切换（L2+战斗中）；传送（L2+）；商店摩拉购买（L2+）；食物/药剂使用（L2+战斗中）。

### 3.4 时间边界

| 限制项 | 默认值 | 说明 |
|--------|--------|------|
| 单次自主最大时长 | 120 分钟 | L3 强制 |
| 强制休息间隔 | 每 60 分钟休息 5 分钟 | L3 强制 |
| 会话时间预算 | 用户设定（默认 180 分钟） | 超后归还控制权 |
| 单任务超时 | 30 分钟 | 超时跳过 |
| 空闲超时 | 10 分钟无进展 | 防止无限循环 |

## 第四章：用户通知与反馈系统

### 4.1 通知分级

| 等级 | 名称 | 颜色 | 定义 |
|------|------|------|------|
| Info | 信息 | 蓝色 | 状态更新/进度报告，无需操作 |
| Warning | 警告 | 黄色 | 需关注，不紧急但建议处理 |
| Critical | 严重 | 红色 | 需立即决策，Agent 已暂停 |
| Emergency | 紧急 | 红色闪烁 | 紧急情况，Agent 已停止 |

### 4.2 通知方式与频率

| 等级 | 显示方式 | 声音 | 弹窗 | 推送 | 最大频率 |
|------|----------|------|------|------|----------|
| Info | 底部滚动条 | 无 | 无 | 无 | 30s/条 |
| Warning | 右下角卡片 | 短提示音 | 无 | 可选 | 60s/条 |
| Critical | 居中弹窗 | 警告音 | 需要 | 可选 | 立即 |
| Emergency | 全屏覆盖 | 紧急音 | 需要 | 强制 | 立即 |

### 4.3 通知内容格式

```
[等级图标] [标题]
[时间戳] | Level [等级]
---
[摘要] 1-2 句话
[上下文] 相关状态信息
[建议操作] 用户可以做什么
---
[按钮1] [按钮2] [按钮3]
```

### 4.4 通知免打扰策略

| 场景 | 免打扰等级 | 行为 |
|------|------------|------|
| Boss 战进行中 | Info/Warning | 延迟到战斗结束 |
| 过场动画/对话 | Info/Warning | 延迟到结束 |
| 用户手动操作 | Info/Warning/Critical | 仅 Emergency 打断 |

免打扰期间通知暂存队列，结束后按序展示。Critical/Emergency 在免打扰期仍显示角落简要提示。

### 4.5 历史通知回顾

环形历史（最近 100 条），支持时间排列、等级筛选、关键词搜索、截图缩略图、JSON 导出。

## 第五章：冲突解决

### 5.1 用户手动操作冲突

**检测：** MouseDeltaMonitor (> 200px/s) + KeyboardMonitor (非 Agent 按键) + 预期状态与实际状态对比。

**解决：** 检测到用户输入 -> 立即释放所有 InputLease -> 2s 观察期 -> 分析用户意图 -> 用户停止操作 5s 后询问"我可以继续吗？" -> [继续]/[暂停]/[取消任务]。

**上下文更新：** 重新截图对比差异 -> 更新 StateBus Observation -> 调整执行计划。

```
用户输入检测详细流程
====================
1. 检测到用户输入
2. Agent 立即释放所有 InputLease
3. 进入 2s 观察期（不执行任何操作）
4. 分析用户操作意图
   - 用户完成操作后 5s 内无新输入 → Agent 继续执行
   - 用户持续操作 → Agent 保持待命
5. 5s 后询问用户："你操作完了？我可以继续吗？"
   - [继续] → Agent 恢复执行
   - [暂停] → Agent 进入 Level 0
   - [取消任务] → Agent 放弃当前任务
```

### 5.2 操作被游戏拒绝

**检测：** 视觉验证操作是否生效 + UI 状态检测（错误提示/冷却指示器/灰色按钮）+ ProgressSupervisor frustration 指标。

**解决：** 检测未生效 -> 等待 500ms-2s -> 重试最多 2 次 -> 分析失败原因 -> 自动修正重试 -> 替代方案 -> 全部失败则通知用户。

**常见原因与处理：**

| 拒绝原因 | 检测方式 | 处理方案 |
|----------|----------|----------|
| 技能冷却 | 冷却指示器识别 | 等待冷却或切换角色 |
| 副本未解锁 | UI 提示文字识别 | 通知用户，跳过此副本 |
| 活动时间已过 | 时间检查 + UI 提示 | 通知用户，更新任务列表 |
| 背包已满 | UI 提示 | 整理背包或通知用户 |
| 体力不足 | 体力条识别 | 等待恢复或使用食物 |
| 距离过远 | 目标与当前位置对比 | 移动到合适位置后重试 |

### 5.3 指令队列冲突

**原则：** 安全优先 > 用户意图优先 > 效率优先 > 原子性（ActionBlock 不中断）。

| 冲突类型 | 策略 |
|----------|------|
| 新指令覆盖旧指令 | 新优先，旧暂停（可恢复） |
| 不冲突的并行任务 | 按优先级排序，合并路径 |
| 任务与安全冲突 | 安全优先，拒绝不安全步骤 |
| 任务与资源预算冲突 | 预算优先，跳过超预算步骤 |

### 5.4 持续失败检测

基于 ProgressSupervisor 的 EWMA frustration 检测（非单帧判断）。

```python
# 基于项目已有 ProgressSupervisor 的配置
failure_detection_config = {
    "consecutive_fail_threshold": 3,    # 连续失败次数阈值
    "frustration_threshold": 0.8,       # frustration 指数阈值（0-1）
    "time_window_seconds": 120,         # 时间窗口
    "slope_threshold": -0.05,           # 进度斜率阈值（负值表示倒退）
}
```

**解决流程：** 连续失败 3 次以上 -> 暂停 -> 分析失败模式 -> 尝试替代策略（切换角色/调整路线/使用道具）-> 替代也失败则逐级降级（L3->L2->L1->L0）-> 记录失败上下文到 Telemetry。

## 第六章：典型人机协作场景

### 场景 1：日常委托中断

```
时间线：
00:00  用户："帮我做日常"
00:01  Agent：交接检查 -> 通过 -> 进入 L2
00:02  Agent：状态同步（蒙德城，树脂 184，4 个委托待完成）
00:03  Agent：开始执行日常委托
...
08:30  Agent：已完成 3/4 委托
08:31  用户：突然想打世界 Boss -> 手动操作鼠标移动
08:31  Agent：检测到用户输入 -> 释放控制权 -> 进入 L0 待命
08:32  用户：手动打完 Boss
08:45  用户："继续做日常"（或按 F8）
08:45  Agent：重新状态同步 -> 发现还有 1 个委托 -> 恢复 L2
08:50  Agent：完成最后一个委托 -> 领取凯瑟琳奖励 -> 归还控制权
08:51  Agent：归还通知（执行摘要 + 当前状态 + 建议下一步）
```

关键点：用户接管即时，不需要等待 Agent 完成当前步骤；未完成任务上下文保留；归还包含完整执行摘要。

### 场景 2：主线解谜降级

```
时间线：
00:00  用户："帮我推主线，做到稻妻第一章"

15:01  Agent：尝试解谜 -> 失败（不熟悉此解谜方案）
15:05  Agent：重试 2 次 -> 仍然失败
15:06  Agent：自动降级到 L1
15:06  Agent：通知用户"遇到解谜需帮助"
        建议："检测到 4 个雷元素方碑，但不确定正确顺序。

关键点：Agent 识别能力不足主动降级；通知包含具体建议和操作指南；用户完成后无缝恢复。

### 场景 3：挂机过夜日常

01:30  Agent：树脂用完（消耗了 180 树脂）
01:30  Agent：检查剩余任务 -> 无 -> 通知用户

```

关键点：L3 通知最小化，不打扰用户休息；任务完成后自动停止；次日用户可查看执行摘要。

### 场景 4：操作冲突

```
时间线：

### 场景 5：游戏崩溃恢复

```
时间线：
00:00  用户："帮我打周本"

关键点：崩溃检测即时（FocusState 监听）；所有输入立即释放不会残留；恢复需用户确认。

| 检查项 | 频率 | 异常处理 |
|--------|------|----------|
