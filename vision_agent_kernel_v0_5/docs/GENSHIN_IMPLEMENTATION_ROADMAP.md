## 第一章：能力依赖图分析

### 1.0 分析概述

274 项主清单能力及 210 个 Corner Cases 构成复杂依赖网络。以下分析识别各层级的依赖关系，为里程碑划分提供依据。

### 1.1 基础层（Layer 0 — 必须最先实现）

这些能力是整个系统的地基，没有任何前置依赖：

```
┌─────────────────────────────────────────────────────────────────┐
│                     基础层 (Layer 0)                           │
├─────────────────────────────────────────────────────────────────┤
│ 感知类 (Perception)                                            │
│   P-01: 屏幕状态识别 (大世界/战斗/对话/加载/菜单)                │
│   P-02: 战斗指示器检测 (红光闪烁/伤害数字/仇恨指示)               │
│   P-06: 对话框检测 (对话框出现/选项/NPC肖像)                      │
│   P-07: 加载画面检测 (加载中防护误操作)                          │
│   P-08: 死亡/复活画面检测                                        │
│   P-09: 弹窗/通知检测 (成就/升级/邮件提示)                       │
│   P-22: 菜单文字OCR (角色属性/材料数量/商店价格)                 │
│   P-26: 场景整体理解 (VLM分析当前屏幕语义)                       │
│   P-27: 可交互物体识别 (NPC/物品/机关)                            │
│   P-28: 敌人类型识别 (种类/元素/护盾类型)                        │
├─────────────────────────────────────────────────────────────────┤
│ 输入类 (Input)                                                  │
│   I-01: 键盘输入 (WASD/E/Q/1-4/F)                                │
│   I-02: 鼠标移动/点击                                            │
│   I-03: 按键组合 (Alt+1~4/Shift冲刺)                             │
│   I-05: 窗口焦点保护 (输入前验证焦点)                            │
│   I-06: 死人开关 (租约过期→立即释放所有按键)                     │
│   I-07: 紧急停止 (F9/Ctrl+C/看门狗→release_all)                  │
│   I-08: 输入租约系统 (所有输入必须通过InputLease授权)             │
├─────────────────────────────────────────────────────────────────┤
│ 对话类 (Dialog)                                                  │
│   D-01: 对话推进 (按F/点击推进对话)                               │
│   D-02: 对话选项选择 (识别选项并选择)                              │
└─────────────────────────────────────────────────────────────────┘
```

**依赖关系**: 无前置依赖，直接实现

**实现复杂度评估**:
- P-01~P-09: S (已有 HSV 颜色分析基础)
- P-22: M (需集成 GLM-4V OCR)
- P-26~P-28: M (需集成 VLM)
- I-01~I-03: S (已有 SafeWindowInputBackend)
- I-06~I-08: S (已有 InputWorker + ModeArbiter)

### M0: 最小可行感知 (MVP Perception)

#### 目标
Agent 能"看到"游戏画面并识别基本元素。

#### 核心能力
```
P-01: 屏幕状态识别 (10种游戏状态分类)
P-06: 对话框检测
P-22: 菜单文字OCR
P-26: 场景整体理解 (VLM)
P-27: 可交互物体识别
P-28: 敌人类型识别
I-01~I-08: 基础输入与安全机制
D-01~D-02: 基础对话
```

#### 验收标准
- 能正确识别 10 种游戏状态（主界面/战斗/地图/菜单/对话/加载/过场/宝箱/死亡/未知）
- 对话框出现时能正确检测
- 菜单文字能正确 OCR 读取
- VLM 能正确理解当前场景语义
- 安全机制正常工作（死人开关/紧急停止）

#### 预计工期
2-3 周

#### 依赖
无

#### 技术风险
1. VLM 响应延迟导致感知不及时 — 缓解：降级到规则化感知
2. 不同区域/时间段的光照变化影响检测 — 缓解：夜间模式适配

#### 降级方案
- VLM 不可用时，使用规则化感知（HSV颜色分析/形状检测）

## 第五章：技术风险评估

### 5.1 Top 10 技术风险

#### 风险1: 实时战斗的操作精度

| 属性 | 值 |
|------|-----|
| 风险等级 | 极高 |
| 概率 | 中 (40%) |
| 影响 | 高 — Boss战需要毫秒级反应，失败率高 |
| 影响范围 | C-19~C-22, C-48~C-54, 全Boss战场景 |

**描述**: Boss 战（如公子三阶段、正机之神）需要精确的时机把握。反应延迟超过 200ms 可能导致角色被秒杀。

**触发条件**:
- 公子 Phase 3 邪眼爆发
- 正机之神击破涅槃引擎窗口
- 女士温度管理临界值

**缓解策略**:
1. 预加载 Boss 动画前摇特征，提前 500ms 开始判断
2. 使用反射闪避优先于主动判断
3. 建立 Boss 机制知识库 (C-22)
4. 允许适度"容错"：损失少量 HP 但不致命

---

#### 风险2: 复杂解谜的逻辑推理

| 属性 | 值 |
|------|-----|
| 风险等级 | 高 |
| 概率 | 中 (50%) |
| 影响 | 中 — 某些解谜卡住不阻塞但影响进度 |
| 影响范围 | E-12~E-18, E-31~E-49 |

**描述**: 立方体解谜(Lightfall Memoir)、沙尘暴导航、梦境循环等需要空间推理或状态追踪。

**触发条件**:
- 稻妻雷立方多面旋转解谜
- 须弥梦境循环记忆
- 枫丹水位控制谜题

**缓解策略**:
1. VLM 辅助理解解谜状态
2. 建立解谜模板库，穷举已知解法
3. 在线攻略搜索作为降级方案
4. 标记无法解决的解谜，人工介入

---

#### 风险3: 感知系统的实时性能

| 属性 | 值 |
|------|-----|
| 风险等级 | 高 |
| 概率 | 高 (70%) |
| 影响 | 中 — 感知延迟影响决策但不直接失败 |
| 影响范围 | P-01~P-57, 全系统 |

**描述**: 60fps 游戏画面检测 + VLM 推理的端到端延迟。VLM 响应通常 500ms-2s。

**触发条件**:
- 快速战斗场景需要即时感知
- 多目标同时出现
- 加载画面与 CG 区分

**缓解策略**:
1. 分层感知：高频规则化 + 低频 VLM
2. VLM 响应超时降级到规则化
3. 帧采样率动态调整
4. 异步感知与同步决策解耦

---

#### 风险4: 跨场景状态一致性

| 属性 | 值 |
|------|-----|
| 风险等级 | 高 |
| 概率 | 中 (40%) |
| 影响 | 中 — 长时间运行可能状态漂移 |
| 影响范围 | S-01~S-09, DL-07, 全系统 |

**描述**: Agent 运行 8 小时以上后，状态可能与实际游戏状态不一致（树脂刷新、任务完成等）。

**触发条件**:
- 跨越刷新时间点的任务执行
- 网络延迟导致的同步问题
- 异常中断后的状态恢复

**缓解策略**:
