副标题：From Failure to Falsifiable Belief Revision
定位：面向长程 Agent 的可证伪信念归因运行时理论

0. v1.1 更新摘要
本版在 v1 基础上补齐以下关键理论修正：
1. Feedback Coupling 时序悖论：将 Belief 生命周期拆分为 Nominal Belief 与 Attributed 
Belief ，把 feedback coupling 从前向入图条件降级为后验质量验证条件。
2. Evidence Matrix 消极稀释问题：替换线性求和公式，引入非对称因果激活，避免大量无关通过信号淹
没一个核心矛盾信号。
3. 多 Auditor 数字妥协问题：加入冲突系数与 Tie-Breaker Popper Probe，禁止在强分歧时简单平均模型
意见。
4. 反事实干预 OOD 退化问题：加入 Counterfactual Priming，确保对 Belief 的 do-干预不会把模型推入
上下文分布外崩溃。
5. CascadeRisk 黑盒问题：给出可计算近似公式。
6. Belief Identity Bootstrap 问题：明确定义 pre-commit 阶段 provisional identity 与 action
materialization 后 confirmed identity。
7. Best-of-N 理论优势边界：给出基于 T 、Terr、Tprefix、attribution overhead 的有界分析。
1. 最终裁定
BAGEL 的最终理论共识是：
长程 Agent 的失败恢复不是盲目重试，而是在有限预算下，用外部可执行反馈、异构审计和伪
证探针，将失败归因到最值得修正的可干预信念单元，并通过安全修正恢复任务轨迹。
最压缩的科学命题是：
Credit assignment over falsifiable beliefs is the missing primitive for self-correcting
long-horizon agents.
对可证伪信念进行信用分配，是自修复长程 Agent 缺失的基础原语。
BAGEL 不声称模型真正“知道自己在想什么”。它采取操作主义立场：
Belief 不是模型内心真实状态，而是上下文中可行动、可证伪、可干预，并且能够在后验审计中
与外部反馈建立经验耦合的行为控制变量。
这使 BAGEL 避免落入“LLM 自省是否可靠”的认识论陷阱。我们研究的不是模型主观意识，而是：
1
修改某个结构化信念单元，是否能可测地改变后续动作与环境反馈分布。
2. BAGEL 解决的根问题
现有长程 Agent 在软件开发、GUI 操作、游戏控制、长期规划中普遍存在以下模式：
1. Agent 在早期形成某个隐式假设；
2. 后续大量动作都建立在这个假设之上；
3. 最终失败反馈往往很稀疏、延迟、离散；
4. Agent 无法判断失败是由哪一个中间假设造成；
5. 系统只能全局重试、语言反思、多 Agent 辩论或扩大采样；
6. 这些方式经常导致 token 浪费、上下文污染、重复犯错和错误传播。
因此，BAGEL 重新定义长程 Agent 失败恢复问题：
给定一条长程 Agent 执行轨迹和外部失败反馈，如何在有限预算下定位、证伪并修正最可能导
致失败的可干预信念集合，使最终交付成功率最大化？
这不是普通 retry 问题，而是：
belief-state credit assignment under executable feedback。
3. 非目标与边界声明
为了避免理论过度宣称，BAGEL 明确不主张以下内容：
1. 不主张 LLM verbalized belief 等于模型内部真实计算状态。
我们只把 belief 视为可干预的运行时控制变量。
2. 不主张 BAGEL 能精确识别唯一真实原因。
失败可能由多个信念组合导致，因此 BAGEL 输出的是高价值候选修正集合，而不是哲学意义上的唯一
真因。
3. 不主张多模型天然偏差正交。
不同厂商模型只是潜在异构性来源，是否有价值必须通过任务上的归因分歧、探针裁决率和历史可信度
经验测量。
4. 不主张 BAGEL 在所有任务上优于 Best-of-N。
BAGEL 的效率优势只在特定条件下成立：持久性信念错误、长程累积结构、局部可修正性和反馈可裁决
性。
5. 不主张每次修正都会单调提升成功率。
信念修正可能破坏偶然正确的下游动作，因此必须引入 Safe Revision 和 cascade risk。
6. 不把 Amortized Failure Memory 作为第一篇论文必须完全兑现的核心贡献。
它是 BAGEL 的长期系统扩展方向和第二阶段研究目标；第一阶段核心贡献集中在 FIG、异构审计、证据
裁决和安全修正。

4. 核心对象：FIG — Falsifiable Intervention Graph
BAGEL 的中心数据结构不是普通聊天记录，不是普通 CoT，也不是传统知识图谱，而是：
FIG：Falsifiable Intervention Graph，可证伪干预图。
形式化定义：
G = (B, A,Y, H, E)
其中：
• B：Belief Nodes，可证伪信念节点；
• A：Action Nodes，执行动作节点；
• Y：Feedback Nodes，外部反馈节点；
• H：Probe Nodes，归因探针节点；
• E：Typed Edges，带类型依赖边。

5. Belief 的严格定义与生命周期
5.1 操作主义定义
BAGEL 中的 Belief 不是任意自然语言想法。它必须是：
一个可行动、可证伪、可干预，并且在后验审计中可与外部反馈变化建立经验耦合的结构化假
设。
为了避免 Feedback Coupling 的时序悖论，BAGEL 将 Belief 生命周期拆分为两个阶段：
Nominal Belief:
 前向注册期。
 只要求满足 action-relevance、falsifiability、intervenability-by-design。
Attributed Belief:
 反向审计期。
 在 failure / probe / revision 后，确认该 belief 的干预与外部 feedback 变化存在经验耦合。
5.2 前向注册条件：Nominal Belief
运行时在 Action 之前无法观测 ，因此不能用 feedback coupling 作为入图条件。
一个 Nominal Belief 只需要满足：
Action relevance：
即它支持至少一个动作，或明确声明将支持某一动作意图。
Falsifiability：

5.4 为什么需要该双时序设计
否则系统会陷入时序逆反悖论：在 Action 和 Feedback 尚未发生时，无法计算互信息；但如果不做前向注册，
又无法建立可审计轨迹。
BAGEL 的回答是：
前向允许结构合格的名义信念进入 FIG；后向用外部反馈过滤其因果质量。

12. Adversarial Probe：伪证优先探针
BAGEL 的 Harness 不是验证器，而是归因探针。

12.1 探针生成约束
LLM 不应自由手写测试。它只选择：
target invariant
mutation operator
expected discrimination
具体 probe 由 deterministic mutator、AST tool、Hypothesis、sandbox 或 GUI detector 生成。
12.2 Probe Sanity
任何 probe 执行前必须通过 sanity check：

是否有明确失败判据；
是否可能产生 timeout/noisy signal；
是否安全；

第 1–4 项优先由规则系统判断；第 5 项在 MVP 阶段可由 LLM 辅助，但必须明确标记为 semantic sanity

15. Lazy Revision 与 Stale Marking
当 hub belief 被证伪时，不应立即重写所有下游节点，否则 token 和时间成本爆炸。
BAGEL 使用 lazy stale marking：
1. 修正 hub belief
2. 将所有依赖它的 downstream nodes 标记 stale
3. 暂不物理重生成全部下游 action
4. 当某个 stale action 即将被执行时，JIT regeneration
5. 执行前运行局部 probe
这避免级联重写，同时不保留错误节点的活跃地位。
16. Best-of-N 挑战：BAGEL 优势的理论条件与有界分析

16.2 BAGEL 优势成立条件
BAGEL 在同预算下优于 Best-of-N 的必要条件至少包括：
条件 1：Persistent Belief Error
失败根源是持久性信念错误，而非随机采样噪声。
18
如果失败只是随机生成质量波动，Best-of-N 更有效。
如果失败来自同一错误信念重复污染后续动作，BAGEL 更有效。
条件 2：Long-Horizon Accumulation
任务具有长程累积结构，同一错误信念会跨多个步骤持续造成失败。
条件 3：Local Revisability
错误是局部可修正的，即修正少量 Belief 后，大部分轨迹或上下文可复用。
条件 4：Executable Feedback Informative
外部反馈或 probe 能提供可裁决信号。
16.3 有界成本分析
设：
• T ：完整轨迹长度；
• Terr：错误信念污染的后续步骤数；
• Tprefix = T − Terr：局部修正后可复用的前缀长度；
• Cattrib：归因成本；
• Cprobe：探针成本；
• Cregen：局部重生成成本，近似与 Terr 成正比；
• N：Best-of-N 的采样条数。
Best-of-N 每次采样需要走完整轨迹：
CostBoN ≈ N ⋅ T
BAGEL 的成本近似为：
CostBAGEL ≈ Tprefix + Cattrib + Cprobe + Terr
因为已有前缀可复用，实际新增恢复成本可写为：
Costrecovery ≈ Cattrib + Cprobe + Terr

Cattrib + Cprobe ≪ (N − 1)Terr

这保证因果分析是在静止世界上进行，避免图版本不一致。

26. 定稿结论
BAGEL 当前理论版本已经达到：
1. 理论自洽：Belief、Feedback、Evidence Matrix、Revision、Audit 均有操作定义；
2. 工程可行：NetworkX + SQLite + sandbox + API model 即可做 MVP；
3. 实验可证伪：每个核心模块都有对应消融；
4. 边界诚实：明确承认不适用所有任务，不承诺绝对因果识别或必然收敛；
5. 产品有价值：在长程 coding / GUI / 游戏 / 软件可靠性任务中，有机会显著提升最终交付质量。
因此，BAGEL 可以作为接下来一段时间项目推进的理论指导。下一步应进入 BAGEL-Coder MVP：用最小实现
